# JSON/YAML内部のUI・候補適用先

2026-10-18の設計スナップショット。[公開範囲と時点の注意](README.ja.md#このスナップショットの読み方)を参照。

[設計と集計](README.ja.md) / [全引数](arguments.ja.md) / [正本と候補取得元](catalog.ja.md)

契約根拠に並ぶファイルの役割は[カタログ](catalog.ja.md)で区別する。A-Frameの公開JSON Schemaは参照用、TypeBox/Spec由来のJSONは生成物であり、いずれも受入契約の正本へ読み替えない。

79個の適用規則を、20個の入力引数の131箇所へ展開した。ブロック数・引数数へ加算しない。内部項目はすべて①であり、②③のSchema authoring/dynamic formへ展開しない。

- 固定Schemaの一般的な数値/string/enum/constはSchema rendererが処理。nested_field_templatesは候補/名前scope/再帰/variantなど専用UI例外を列挙し、各親引数へ展開。任意JSON/任意PROPSでは名前の意味を推測しない。
- pathはJSON Pointer風。*は配列項目。node_baseを起点にrecursive_viaを0回以上辿った各ノードへpathを適用する。variantは所有codecが判定し、inactive variantの値を追加/変換しない。property-nameはobjectのキーを編集する。JSON Schemaの$refとは別のUI適用規則。
- 固定shadowのliteralを所有の純粋codecで安全に解析して対象pathを収集する。非literal/不正sourceは評価せずスキップ。definitionは予定名であり登録済みを意味しない。既存下書きと保存済みliteral、実行registryを区別し、instance/target/session/reference/camera/capability contextを保持する。
